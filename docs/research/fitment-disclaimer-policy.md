# Fitment Disclaimer Policy

Purpose: define how CertiSpares should discuss fitment, compatibility, vehicle models, and confirmation requirements.

## Core Fitment Position

CertiSpares should not claim exact fitment unless it has been confirmed through appropriate technical data.

Fitment language should stay in the zone of:

- common application context
- typical systems handled
- matching inputs
- confirmation requirements
- RFQ discussion

It should not become:

- official fitment advice
- model-wide compatibility promises
- universal replacement claims
- dealer or OEM authorization claims

## Reusable Global Disclaimer

Use this site-wide:

> Brand names, OE numbers, vehicle models, and cross references on this site are used for inquiry identification and matching discussion only. Final fitment and quotation scope must be confirmed by OE reference, VIN, model/year/market data, dimensions, connector type, and other applicable technical specifications. CertiSpares is an independent sourcing and RFQ support service unless explicit authorization is stated.

## Short Disclaimer Variants

Short version:

> Final matching depends on OE/VIN/model/spec confirmation.

RFQ CTA version:

> Send OE number, VIN/model, photos, dimensions, and destination so the quotation scope can be checked before sourcing.

P2 brand version:

> CertiSpares provides independent aftermarket inquiry support and does not represent an official dealer or service network unless explicit authorization is stated.

Product-family version:

> Application context is provided for inquiry preparation only. Final fitment must be confirmed against OE reference, vehicle details, and technical specifications.

## Page-Type Guidance

Brand pages may show:

- typical systems handled
- common buyer inquiry inputs
- platform or family context
- related systems and product families

Brand pages should not show:

- broad exact-fit model tables
- "fits all" language
- official dealer language

System pages may show:

- fitment drivers
- match-critical fields
- examples of details that affect matching

System pages should not show:

- universal compatibility statements
- unsupported application lists

Product-family pages may show:

- common application context
- key variables
- required specs
- mismatch risks

Product-family pages should not show:

- SKU-level exact fitment unless verified
- fake interchange tables
- price/stock/lead-time promises

RFQ pages should show:

- clear confirmation requirement
- upload and detail prompts
- context from the entry page

## Fitment Drivers By Category

Examples:

- Brake: VIN/model, drum/disc dimensions, brake type, OE reference
- Suspension: bushing size, pin size, torque rod length, load spec
- Electrical: voltage, connector type, plug pins, mounting, OE reference
- Engine: engine model, OE reference, configuration, photos
- Cooling: dimensions, inlet/outlet position, core size
- Axle and wheel-end: axle model, bearing dimensions, bolt pattern

## Forbidden Language

Avoid:

- fits all
- guaranteed fit
- exact replacement for all models
- official replacement
- genuine part unless verified
- OEM authorized unless verified
- dealer alternative
- same as original unless verified

## Acceptance Criteria

Fitment language is acceptable if:

- it helps the buyer prepare an inquiry
- it asks for confirmation inputs
- it avoids official or exact-fit overclaims
- it is visible on page where schema or SEO copy refers to it
- it routes uncertainty into RFQ instead of pretending certainty
